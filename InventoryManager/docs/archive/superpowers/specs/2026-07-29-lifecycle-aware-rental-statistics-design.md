# 按生命周期日期统计出租数据设计

## 背景

出租周期统计目前先按设备的当前生命周期状态做全局排除。因此，设备一旦被标记为已出售、已停用、已损坏或已退役，该设备的全部历史订单、出租率分母和折旧都会从统计中消失。

系统同时保留了旧的 `Device.status = online/offline` 和新的 `Device.lifecycle_status` 两套可用性状态。旧状态没有独立的生效日期，自动更新服务也只保持当前值；设备是否可用应统一由生命周期状态表达。

## 目标

- 已出售、已停用、已损坏或已退役设备的历史订单继续参与统计。
- 出租率分母和折旧按设备实际投入日期至生命周期状态生效日期之间的天数精确折算。
- 状态生效当天不再计入可用天数、折旧或新开始的订单。
- 删除旧的 `online/offline` 状态及其前后端业务逻辑。
- 年化预测的历史部分保留已退出设备贡献，未来部分只使用当前活动设备。

## 非目标

- 不新增销售金额、残值或资产处置收益字段。
- 不维护完整的生命周期状态变更历史；本次只使用当前非活动状态及其 `lifecycle_date`。
- 不改变取消订单、附件订单和代发设备的既有统计口径。
- 不修改订单日期或设备生命周期日期。

## 统一设备状态

设备可用性只由 `lifecycle_status` 表达：

- `active`：可接收新租赁并参与当前和未来容量统计。
- `sold`：已出售。
- `decommissioned`：已停用。
- `damaged`：已损坏。
- `retired`：已退役。

四种非活动状态均以 `lifecycle_date` 作为不可用生效时间。

数据库迁移规则：

1. `status = offline` 且 `lifecycle_status = active` 的设备保持或设置为 `active`，不生成 `lifecycle_date`。
2. `status = online` 且 `lifecycle_status = active` 的设备保持 `active`。
3. 已经处于四种非活动生命周期状态的设备保持原状态和原 `lifecycle_date`，不被旧 `status` 覆盖。
4. 完成数据归并后删除 `devices.status`。
5. 降级迁移重新创建 `status` 时统一写入 `online`；已删除的旧 `offline` 值不恢复。

应用层同步删除：

- 设备状态编辑和筛选接口中的 `online/offline` 参数。
- PC 和移动端的在线、离线标签及编辑入口。
- `DeviceStatusService`、相关定时任务和强制更新路由。
- 租赁、档期查找和重排中的 `status == online` 判断，统一改为 `lifecycle_status == active`。
- API 数据结构和前端类型中的旧 `status` 字段。

## 统计服务区间

仅统计非附件、自营设备。代发设备名称黑名单继续永久排除，因为它们不属于自营资产。

旧的 `2005/3005/3006` 损坏或停用设备名称黑名单删除。这些设备改用生命周期状态和日期确定历史统计边界。

每台设备建立半开服务区间：

```text
[first_order_date, lifecycle_date)
```

- `first_order_date` 是该设备第一笔未取消主订单的开始日期。
- `active` 设备的区间没有结束时间。
- 非活动设备的结束时间为 `lifecycle_date` 所在自然日零点。
- 非活动设备缺少 `lifecycle_date` 时不猜测日期，也不删除历史；统计接口记录警告并把查询结束日作为临时上限，使已有历史仍可见。

使用半开区间意味着生命周期状态生效当天不再产生容量和折旧，也不统计当天或之后开始的新订单。

## 周期统计

每个周或月周期也转换为半开区间：

```text
[period_start, period_end + 1 day)
```

单台设备在周期内的有效天数为服务区间与周期区间交集的自然日数。

### 订单

保留满足以下条件的主订单：

- 状态不是 `cancelled`。
- 开始日期位于查询周期内。
- 开始日期位于设备服务区间内。

设备退出前开始的历史订单保留；退出当天及之后开始的订单不计。

### 出租率

周期容量按实际可用天数计算：

```text
available_device_weeks = 所有设备有效天数之和 / 7
rental_rate = order_count / available_device_weeks
```

周和月使用同一公式。这样月中投入或退出的设备只贡献实际可用天数。

响应中的 `device_count` 继续表示该周期至少有一天可用的设备数量，保持表格含义；新增或内部保留 `available_device_weeks` 作为出租率分母，避免用整数设备数冒充精确容量。

### 折旧

折旧函数使用设备服务区间与周期区间的交集：

- 从 `first_order_date` 开始折旧。
- 最晚折旧到 `lifecycle_date`，不包含状态生效当天。
- 没有有效交集时折旧为零。

利润和净利润继续使用现有公式，只替换周期折旧输入。

## 年化预测

- 历史订单查询包含所有曾投入的自营设备，并按各自生命周期结束日裁剪。
- 历史折旧对每台设备只计算到生命周期结束日或历史统计截止日中的较早者。
- 当前和未来收入、容量及折旧预测只使用 `lifecycle_status = active` 的设备。
- 累计投资成本保留所有进入历史统计的设备采购成本；本次不推断销售回款或资产残值。
- 新增设备预测逻辑保持不变。

## 错误与兼容处理

- 非活动设备缺少 `lifecycle_date` 时不得重新全局排除历史数据；服务端输出可定位设备 ID 的警告。
- 无第一笔有效主订单的设备不进入出租率分母或折旧。
- 旧客户端提交 `status` 筛选或更新字段时返回明确的参数已移除错误，不静默接受。
- 数据库迁移在删除字段前完成旧值归并；迁移失败时事务回滚。

## 测试策略

### 后端统计

- 已出售设备在出售前的订单、收入和利润仍被统计。
- 出售当天及之后开始的订单不被统计。
- 月中出售设备只按出售前自然日数进入出租率分母。
- 折旧在生命周期日期处截止。
- `sold`、`decommissioned`、`damaged`、`retired` 四种状态使用相同边界规则。
- 当前 `active` 设备保持完整周期统计。
- 代发设备仍永久排除，原损坏设备名称不再被永久排除。
- 缺少 `lifecycle_date` 的非活动设备保留历史且产生警告。
- 年化预测历史包含退出设备，未来预测排除退出设备。

### 状态归并

- 旧 `offline + active` 数据迁移后为 `active`，且不生成生命周期日期。
- 旧 `offline` 不覆盖已有非活动生命周期状态。
- 新租赁、档期查找和重排只接受 `active` 设备。
- 后端与前端不再提供在线、离线状态编辑或筛选。

### 回归

- 取消订单和附件订单仍不进入主订单统计。
- 型号筛选、周月切换、汇总行和 CSV 导出保持可用。
- PC 与移动端构建、后端单元测试和迁移升级测试通过。
