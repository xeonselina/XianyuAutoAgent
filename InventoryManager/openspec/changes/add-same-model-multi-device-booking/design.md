## Context
每台主机已有独立 Rental，parent_rental_id 专用于库存附件。本实现保留此关系，增加 RentalBooking 关联同单主机。

## Decisions
- 两台共用型号、仓库、租期和收件信息；第二台独立保存镜头和附件，最多两台。
- POST /api/rentals 保持原单台字段，增加 additional_devices（最多一个）、booking_request_id 和可选 append_to_rental_id。兼容返回 main_rental，同时返回 main_rentals。
- RentalBookingRequest 以 UUID 主键记录请求内容哈希和创建的 ID，同一数据库事务内提交。重试返回原记录，内容不同的已用请求标识被拒绝；浏览器通过 getRandomValues 支持局域网 HTTP。
- 批次内按设备 ID 排序锁定全部主机及附件，复用原服务的库存检查；内部创建仅 flush，外层统一 commit。保留原 409 库存/仓库错误码。
- 同店铺订单创建通过店铺行锁串行化，防止两次同时补齐；没有外部订单号时依赖原主机锁和重新读取原单。真实 MySQL 并发仍需专用测试库验证。
- 两台订单总额存于关联记录，Rental.order_amount 均摊，尾差归另一台，旧统计按租赁汇总也不会翻倍。订单报表去重同单，设备出租率及物流成本仍按设备台数计算。
- 补齐旧单需用户确认，declare-booking 先保存应录两台；即使退出表单或下一次保存失败仍保留 1/2 提醒。历史多条同号记录不自动合并。
- 同单公共字段和分摊金额暂不允许从单台编辑修改；避免只修改一台破坏同租期/同地址。单台镜头、库存附件、状态仍可独立编辑。需要统一修改公共字段的交互留待后续。
- 取消不自动减租；reduce-booking 要求仅剩一台有效记录、减租原因和新的总额，并记录审计日志。
- 甘特图、详情、客户确认信息、图片发货单及网页发货单标记同单和每台配置。详情提供查看另一台。
- 同单全部填入相同运单后允许回传，保存已回传运单避免重复通知；多运单拆包返回明确提示，由用户到闲鱼手动处理，不覆盖现有运单。外部接口成功但事务提交前进程中断仍存在重试窗口，与外部系统没有分布式事务，需平台联调验证。
