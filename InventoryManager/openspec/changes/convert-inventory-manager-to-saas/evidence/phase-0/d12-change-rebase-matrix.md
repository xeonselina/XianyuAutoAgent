## P1 closure notes made explicit by this matrix

The following were materially under-specified in the earlier three-column summary. They are now recorded as mandatory preservation or supersession boundaries, not new product decisions:

1. `integrate-xianyu-order-api` includes order-detail fetch, rental-form autofill, and revenue tracking/statistics; it is not only a credential/cursor/sync change. A concrete implementation task and test mapping is still required before its rebase can be called complete.
2. `add-xianyu-missing-order-alerts` includes permanent ignore with reason and BookingDialog reuse; both remain tenant-scoped product capabilities.
3. D73 supersedes any implicit single-shop assumption in the rows above: one tenant may own multiple Xianyu Manager accounts/shops, and every alert, rental, query, and shipment operation keeps its connection identity through durable execution.
3. `add-scheduled-shipping-status` includes the individual waybill-print sub-capability; it must converge on the approved paired-label durable print model rather than disappear with the old A4 document.
4. `add-relay-management` includes shipment tracking from its worktable; historical shipment credential snapshots govern that query.
5. `add-single-rental-ship-button` keeps the UI entry, but browser loading state is not an idempotency boundary and full order/tracking identifiers are not acceptable ordinary logs.
6. `simplify-batch-shipping-flow` keeps automatic waybill generation, but its old full-provider-context logging and synchronous submission model are superseded by safe correlation, ledger, outbox, and reconciliation.
7. `interleave-shipping-slips-with-waybills` is retained only as the fixed first-sheet/second-sheet workflow; the optional independent shipping-slip identity and old field set are superseded.
8. `add-gantt-schedule-reordering` keeps reordering and confirmed relay intent, while legacy overlap/accessory/binding implementation details must obey D33/D39 and the current warehouse model.

No new Core product decision was discovered during this D12 audit. These boundaries followed the then-approved D01–D60 decision table and superseding records; later D61 credential-risk, D62 scheduling, and D63/D64 simplification decisions update the Phase 0/12 sequence without changing this capability disposition matrix.
