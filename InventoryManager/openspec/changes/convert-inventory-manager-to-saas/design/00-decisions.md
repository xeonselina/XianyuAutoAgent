# SaaS 转型设计：决策协议

> 返回：[总体设计索引](../design.md)

## 0. Decision Protocol

所有关键决策使用下表管理。只有项目负责人与方案方讨论后，状态才能改为“已确认”；“建议”不等于“决定”。每次讨论只聚焦 1–2 个强相关问题，确认后记录选择、理由、日期及会被影响的章节。

| ID | 决策主题 | 主要候选 | 当前建议 | 状态 |
|---|---|---|---|---|
| D01 | 租户数据隔离模型 | 共享表 / 每租户独立库 / 混合模式 | 每租户独立业务库和独立最小权限数据库账号，共享 MySQL 实例，预留跨实例路由 | 已确认 |
| D02 | 首发范围 | 仅 SaaS Core / Core + 自助商业化一次上线 | SaaS Core 先行 | 已确认 |
| D03 | 开通方式 | 邀请制 / 开放注册 / 销售后台开户 / 兑换码 | 单次兑换码注册或续期；码绑定套餐、服务时长和兑换截止时间 | 已确认 |
| D04 | 登录标识与会话 | 邮箱/手机号/用户名；服务端 Session/签名 Cookie/JWT；单/多租户账号 | 手机号 + 短信验证码无密码登录；一个账号只归属一个租户；浏览器使用 D45 的 MySQL 服务端逐设备会话和安全 Cookie | 已确认（经 D45 补充） |
| D05 | 角色与 PII 权限 | 固定角色 / 自定义角色；客户信息可见范围 | 使用两个完全分离的身份域：平台身份域只有全局 `platform_admin`，租户身份域只有 Admin、Operator；无 Viewer。平台管理员按 D43 独立认证，并按 D44 跨租户只读业务数据 | 已确认（经 D43–D44 补充） |
| D06 | 套餐与收款 | 兑换码 / Stripe / 微信支付宝 / 合同账单；套餐额度 | Core 单一套餐：兑换码服务期；有效成员与未过期待接受邀请合计最多 10 个；按 D51 不设其他业务硬额度；在线支付延后 | 已确认（Core） |
| D07 | 第三方账号归属 | 租户自带 / 平台共享 / 两者并存 | 闲鱼/顺丰/快麦租户自带；短信平台提供；OCR 移除 | 已确认 |

| D09 | 异步任务技术 | Celery/RQ / MySQL 任务表 / Web 内调度 | MySQL 持久化任务表 + 单个独立后台进程 | 已确认 |
| D10 | SLA 与数据治理 | 可用性、RPO/RTO、保留/注销周期 | 数据库采用小时级恢复点、标称 RPO 约 1 小时；NAS 保留 48 个小时、30 个每日、12 个每月成功备份；整台云主机损坏后以 4 小时作为初期内部演练参考目标，不是客户 SLA、赔偿承诺或发布硬门槛，完成点按 D59。Core 对外不承诺数值可用性 SLA、严格 RPO 或停机/数据损失赔偿；自然到期永久保留，Admin 主动删除采用受控 30 天流程且审核通过即冻结业务；删除完成后普通成员手机号可用于全新租户身份。正式对外前手工完成一次全新主机恢复，此后不自动调度或设固定周期；第二异机副本使用 NAS 既有云盘同步 | 已确认（Core） |
| D11 | 现有数据迁移 | 默认租户映射、Admin、凭证所有权、切换窗口 | 新建 `inventory_control`，将当前业务 schema 原地注册为第一个默认租户数据库；不复制整库、不改成共享 `tenant_id` 表。现有数据和第三方配置的业务归属进入默认租户，新租户才创建新库；D61 覆盖的旧 SF/快麦值不得作为 Core revision 迁移，首次演练前只录入轮换后重新验证的新值。默认租户显示名称和首位 Admin 手机号在首次迁移时作为必填部署参数录入，不设代码默认值。维护窗口内、尚未开放新版业务写入时可回滚旧应用；开放后只回滚到 tenant-aware 版本或 forward-fix。首次切换提前 24 小时通知并预留 2 小时维护窗口，目标停写不超过 30 分钟，60 分钟内未通过验证即回滚 | 已确认（经 D61 补充） |
| D12 | 活跃业务变更排序 | 先完成 / 暂停 / 保留并随 SaaS 适配 | `select-sf-express-type` 在切换前收尾，`add-rental-damage-notes` 按已完成归档；只暂停旧 A4 独立发货单与旧扫码发货流程，其余 13 项能力全部保留并随租户、仓库、provider job 和聚合 API 边界适配。该分类继续生效；D63 已取消 D12/D62 后加的代码、schema、核心模块冻结及持续到切换后 48 小时的流程 | 已确认（冻结部分经 D63 取代） |
| D13 | 功能裁剪与租户品牌 | 保留/移除文档能力；固定/自定义公司信息 | 移除 OCR/合同/独立发货单页面；保留顺丰第一联与本地寄回第二联；租户品牌可配置 | 已确认（经修订） |
| D14 | 多仓库工作流 | 选货排序、主件/附件仓库规则、发货/验货仓库、打印机绑定、调仓 | 优先仓只影响主设备选货；附件与主设备同仓；一订单一发货仓/包裹/运单；发货/打印/验货按账号记忆仓库；每仓一台面单打印机；Core 即时调仓、不建调拨单；首次登录完善默认仓 | 已确认（核心流程；运单后调仓和跨仓附件验收分别经 D40–D41 确认） |
| D15 | 附件库存模型 | 序列化实物 / 设备配套 / 聚合数量 / 逻辑库存单元 | 附件类型可配置到具体设备；手柄/镜头支架为设备配套，手机支架/三脚架每份容量创建仅内部可见的逻辑单元。订单仍只勾选附件类型，系统自动建立单元关联并实时聚合数量；设备调仓重新求解未来关联，不足则动态显示冲突并执行发货门禁或已确认的接力例外 | 已确认（经 D39 修订） |
| D16 | 页面 API 扇出与实时性 | 逐资源请求 / 批量 API / 页面聚合；本地或服务端缓存 / 实时查询 | 预约使用 bootstrap + 单次实时 availability；甘特图使用单次范围 view；页面唯一负责写后最多一次刷新；禁止库存敏感业务数据跨请求缓存；其他页面按审计结果分级合并 | 已确认（Core） |
| D17 | 档期占用时间口径 | 客户使用期硬冲突 / 完整物流窗口硬冲突 / 物流重叠软警告 | 主设备按首尾均包含的客户使用期判断硬冲突；计划寄出/回仓日期继续包含物流天数和前后各 1 天缓冲，但相邻订单物流窗口重叠不再自动阻止建单。计划日期与实际物流事件分字段 | 已确认（经 D33 修订） |
| D18 | 闲鱼告警新鲜度与轮询 | 每账号 60 秒轮询 / 租户级后台同步 / 手动刷新 / 推送 | 后台按租户每 3 分钟同步第三方；可见页面每 3 分钟只读租户库告警摘要；用户手动刷新提交即时高优先级同步并复用在途任务 | 已确认（Core） |
| D19 | 多仓物流时效估算 | 固定深圳起点 / 优先仓 / 实际设备仓；静态规则 / 顺丰接口 / 人工值 | 实际设备仓 → 客户结构化地址；顺丰官方查询优先，地址/provider 不可用时由 Admin/Operator 明确填写并确认；禁止固定深圳或静默默认 3 天 | 已确认（建单） |
| D20 | 仓库顺丰月结账号 | 租户全局账号 / 每仓账号；共享 API credential / 每账号 credential；一对一 / 可复用 | 每仓绑定一个活动月结账号，同一月结账号在全平台不得同时绑定多个仓库；租户默认共享一组 API connection，特殊月结账号可显式引用独立 connection；所有动作由设备实际仓自动路由，客户端不能临时选账号 | 已确认（全平台禁止复用经 D42 定稿） |
| D21 | 建单后调仓的物流重算 | 保留原估算 / 自动重算 / 仅提示；是否改变计划物流窗口 | 调仓时列出受影响 rental 并提示用户自行检查；系统不自动重算或修改既有物流天数、计划寄出/回仓日期、物流窗口和估算快照，也不新增仅因物流时效未复核产生的发货门禁。若既有运单与新仓不一致，则按 D40 阻断打印/实发并要求取消重建 | 已确认（物流字段） |
| D22 | Core MySQL 部署拓扑 | 同机 Docker / 独立自建主机 / 云数据库 | Core 暂时让应用与共享 MySQL 实例运行在同一台云主机的 Docker Compose；接受单机故障域，保留迁往独立/托管实例的路由能力；异机备份与恢复演练是上线门槛 | 已确认（阶段性） |
| D23 | 数据库异机备份传输 | 云主机推送 / NAS 主动拉取 / 云备份服务 | 家庭 NAS 每小时主动 SSH 连接云主机，触发受限的一致性 full dump 并下载；保留 48 小时/30 日/12 月层级。full dump 连续三次超过 20 分钟或明显影响业务后切换每日 full + 小时 binlog | 已确认（Core） |
| D24 | NAS 数据库备份静态加密 | restic/加密卷 / 不加密 | Core 不对 NAS 上的 dump 文件或备份目录做静态加密；SSH 仅保护传输。使用压缩、checksum、专用不可共享目录、最小权限和只读快照作为补偿控制，并明确接受 NAS 失陷/被盗后客户数据可读的剩余风险 | 已确认（风险接受） |
| D25 | 到期租户数据保留 | 90/180/365 天后删除 / 永久保留 | 兑换码服务期到期只停用业务访问，不自动删除或归档掉租户数据库；数据库永久保留并持续纳入备份与 schema migration，续期后原数据恢复可用。租户主动申请删除仅按 D26 的显式例外流程执行 | 已确认（风险接受） |
| D26 | 租户主动删除 | 永不删除 / 一键删除 / 受控延迟删除 | Core 不提供一键 hard delete；租户 Admin 经短信复验发起，平台人工复核后进入 30 天冷静期，期满删除在线 tenant schema 和租户业务/凭证数据，仅永久保留无业务内容的删除 tombstone。旧 NAS 备份按既定保留期自然淘汰，任何恢复必须先应用最新 tombstone ledger，禁止复活已删除租户 | 已确认 |
| D27 | 删除冷静期访问 | 正常使用 / 只读 / 立即冻结业务 | 平台管理员批准删除申请时立即冻结租户业务：Operator、既有 session、定时/第三方任务全部停用；Admin 只能访问删除倒计时、撤销和账号安全。撤销后按当时真实订阅/平台状态恢复，不补偿或顺延冷静期服务天数 | 已确认 |
| D28 | 删除后手机号重用 | 永久封禁 / 延迟释放 / 删除完成即释放 | D26 完成前所有成员手机号仍归原租户且不能加入其他租户；完成后删除 tenant-only 用户身份并立即释放手机号，可凭新兑换码注册或接受新邀请。新注册生成全新 user/tenant/database UUID，绝不连接旧数据；独立平台管理员身份不随租户删除 | 已确认 |
| D29 | Core RPO 承诺 | 严格 ≤60 分钟 / 小时级内部目标 / 不设目标 | 每小时生成恢复点并以约 1 小时作为内部目标，最新成功恢复点年龄超过 90 分钟告警；dump 耗时、失败和 NAS 离线可能扩大实际窗口。对外只描述小时级备份，不承诺最大数据损失窗口或相关赔偿 | 已确认 |
| D30 | 灾备演练调度 | 月度自动 + 季度人工 / 固定人工周期 / 维护者按需手工 | 正式对外前必须手工完成一次全新主机恢复，验证安全覆盖、至少一个租户核心 smoke 和旧副作用隔离，并记录相对 4 小时内部参考目标的实际耗时；超时记改进项但不单独构成发布否决。此后不建立自动恢复任务，也不设置季度或其他强制周期。交付可重复运行的恢复命令、runbook、检查清单和结果记录模板，由项目负责人后期自行选择时间执行 | 已确认 |
| D31 | 第二异机备份副本 | 应用直传对象存储 / NAS 自动同步云盘 / 不增加 | 使用家庭 NAS 已有的自动云盘同步作为第二异机副本；应用和云主机不接入云盘、不保存云盘凭证。仅同步 NAS 已校验完成的 dump/manifest/checksum 和永久 tombstone ledger，不同步 `.partial` 或平台根密钥；具体 provider/保留和同步验证作为部署参数记录 | 已确认 |
| D32 | 云盘备份静态加密 | 客户端加密后同步 / 压缩明文同步 | NAS 将 `.sql.gz` 等压缩明文 artifact 原样同步到云盘，不增加客户端/应用层加密或新的备份密钥；云盘自身默认服务端加密可以保留但不作为机密性边界。使用 MFA、私有目录、禁止分享链接、最小账号权限和版本历史，并明确接受云盘账号/provider 失陷后全部租户客户数据可读的风险 | 已确认（风险接受） |
| D33 | 甘特物流冲突与接力阈值 | 独立规则 / 共用规则；`>0` / `>1` / 其他阈值 | 同一主设备相邻有效订单共用 `ScheduleOverlapPolicy`：`overlap_days = 前单计划回仓日 - 后单计划寄出日`；只有 `> 1` 天才在甘特提示并进入接力候选，`<= 1` 天均不提示。该结果是非阻断警告，不自动修改 rental | 已确认 |
| D34 | 逻辑附件单元接力 | 复制订单需求 / 单元随主设备 / 缺少附件阻断或手工补寄 | 手机支架/三脚架的逻辑单元离仓后随主设备流转；接力 `agreed` 时为后单建立无状态 link，实际交接时才更新持有订单并追加交接事件。中间 rental 未勾选不创建需求或特殊状态，界面从 link 与需求动态提示。后一单需要但当前设备未携带时尝试自动关联其他单元；没有可用单元则显示不足并允许内部补寄备注，不阻止接力进入“已同意”，Core 不新增第二正式运单 | 已确认（经 D39 修订） |
| D35 | 平台短信供应商与签名 | 腾讯云 / 其他国内供应商；平台统一签名 / 每租户签名 | Core 首发腾讯云短信，所有租户共享平台运营主体的一个签名，租户自定义公司名不影响短信签名。企业实名认证、实名资质、签名/验证码模板审核及运营商报备全部完成并通过真实号码端到端测试后，才允许生产注册、登录和短信复验 | 已确认（Core） |
| D36 | 成员邀请通知送达 | 腾讯云邀请短信 / Admin 复制链接线下发送 / 其他渠道 | 腾讯云验证码只用于登录、注册和安全复验；Core 由 Admin 复制单次邀请链接，通过微信等已有沟通渠道发送。受邀者打开链接后仍须用链接绑定手机号完成 `accept_invitation` 验证码校验，链接本身不能直接建立 membership | 已确认（Core；跨租户并行邀请经 D47 补充） |
| D37 | 验证码有效期与防刷阈值 | 宽松 / 平衡 / 严格 | 6 位数字、5 分钟有效、60 秒后可重发、单 challenge 最多错 5 次；每手机号跨用途最多 5 次/小时和 10 次/上海自然日，每可信来源 IP 最多 30 次/小时和 200 次/上海自然日。阈值为版本化部署配置，腾讯云控制台在能力范围内同步为相同限制，避免 provider 与页面规则漂移 | 已确认（Core） |
| D38 | 监控告警接收渠道 | 邮件 / 微信 / 短信 / 电话 / 企业微信 / webhook | 使用腾讯云“消息接收人”绑定维护者个人微信、手机和邮箱：P1 故障全天电话 + 短信 + 邮件，P2 警告微信 + 邮件，恢复通知沿原渠道发送；不要求企业微信或自建告警 webhook | 已确认（Core） |
