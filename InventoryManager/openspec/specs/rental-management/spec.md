# rental-management Specification

## Purpose

记录当前已上线的租赁管理行为，覆盖租赁单的查询、创建、设备与附件选择、编辑、状态和删除。预约、物流、验货等独立功能在此只规定与租赁单直接相接的边界；更细的规则由各自的 capability spec 承担。

## Requirements

### Requirement: 按租户和仓库查询租赁记录

系统 MUST 在当前租户的数据范围内读取租赁记录，并支持按仓库、设备、客户姓名、电话、地址、状态和日期范围筛选。列表 MUST 按租赁 ID 倒序分页返回，每页最多 100 条。

#### Scenario: 按仓库查看记录
- **WHEN** 操作员选择一个仓库查询租赁列表
- **THEN** 结果只包含该仓库的租赁记录

#### Scenario: 组合条件筛选
- **WHEN** 操作员同时提交设备、状态和完整的起止日期筛选条件
- **THEN** 结果只包含满足全部条件、且租赁开始日期不早于筛选起日、结束日期不晚于筛选止日的记录

#### Scenario: 查看单条记录
- **WHEN** 操作员打开一个存在的租赁记录
- **THEN** 系统返回该记录的当前数据；记录不存在时返回不存在错误

### Requirement: 列出已过应归还日的租赁

待归还列表 MUST 只列出所选仓库中，状态为 `shipped`、没有父租赁且结束日期不晚于昨天的主租赁，并显示设备名称、应归还日及逾期天数。

#### Scenario: 显示逾期主租赁
- **WHEN** 一条已发货主租赁的结束日期不晚于昨天
- **THEN** 待归还列表包含该记录、设备名称和逾期天数

#### Scenario: 排除尚未逾期或已寄回记录
- **WHEN** 租赁尚未达到待归还条件，或状态已变为 `returned`
- **THEN** 待归还列表不包含该记录

### Requirement: 创建租赁单时验证基本信息和租期

创建请求 MUST 提供主设备、客户名称、开始日期和结束日期。系统 MUST 验证日期范围及有效占用时间，并将新租赁的初始状态设为 `not_shipped`。

#### Scenario: 创建有效租赁
- **WHEN** 必填信息、租期和设备选择均有效
- **THEN** 系统创建主租赁并返回创建结果

#### Scenario: 缺少必填信息或占用区间无效
- **WHEN** 请求缺少必填字段，或寄出时间不早于收回时间
- **THEN** 系统拒绝创建，且不留下部分租赁记录

### Requirement: 新建租赁时严格验证库存

新建租赁 MUST 使用所选仓库内处于正常可出租生命周期的主设备和库存附件。系统 MUST 拒绝与活动租赁占用时间重叠的设备，且主设备与附件不能重复选择同一库存设备。

#### Scenario: 主设备或附件被占用
- **WHEN** 新建请求选择的主设备或库存附件与另一条活动租赁的有效占用时间重叠
- **THEN** 系统返回设备不可用错误，且不创建租赁

#### Scenario: 设备不属于所选仓库
- **WHEN** 主设备或附件属于其他仓库
- **THEN** 系统返回仓库不匹配错误，且不创建租赁

#### Scenario: 设备已售出或停用
- **WHEN** 新建请求选择非正常可出租生命周期的设备
- **THEN** 系统拒绝该设备选择

### Requirement: 按实际占用时间判断档期冲突

档期检查 MUST 优先使用寄出时间和收回时间；缺失时分别使用租赁开始日的起点和结束日的终点。`not_shipped`、`scheduled_for_shipping`、`shipped`、`returned` 状态占用档期，完成或取消的租赁不再占用档期。

#### Scenario: 物流时间延伸到另一租赁
- **WHEN** 两条租赁的起止日期不重叠，但寄出至收回的有效占用时间重叠
- **THEN** 新建租赁的冲突检查将该设备判定为被占用

#### Scenario: 旧记录缺少物流时间
- **WHEN** 一条活动租赁没有寄出或收回时间
- **THEN** 档期检查使用其租赁日期边界判断冲突

### Requirement: 保持设备型号与租赁组合一致

创建租赁 MUST 使用所选设备型号允许的启用租赁组合，并在租赁上保存组合名称及项目快照。编辑时明确更换设备型号后，原组合不兼容时 MUST 改用目标型号的默认组合；不换型号的历史订单仍保留已保存的组合快照。

#### Scenario: 创建时选择无效组合
- **WHEN** 请求选择设备型号不允许或已停用的租赁组合
- **THEN** 系统拒绝请求，不创建租赁

#### Scenario: 编辑时换成另一型号
- **WHEN** 操作员更换主设备，原组合不适用于新型号
- **THEN** 编辑器或服务端选择新型号的默认组合，并保存新的组合快照

### Requirement: 同单多设备预约原子保存

同单录入的主设备 MUST 属于同一型号，且主设备和库存附件不能在同一次预约或已录同单记录中重复。多设备创建及补齐 MUST 使用请求标识防止重试重复创建，并在同一个事务中保存全部设备及其附件。订单总金额按分精确分摊到同单主租赁；单台编辑不得改写同单公共信息或分摊金额。

#### Scenario: 同单创建两台设备
- **WHEN** 操作员为同一订单选择两台同型号且均可用的主设备
- **THEN** 系统一并创建对应主租赁和附件租赁，并关联同一预约

#### Scenario: 第二台设备校验失败
- **WHEN** 同单的任一设备或附件无效、被占用或跨仓库
- **THEN** 整个创建请求失败，先前选中的设备也不会被部分保存

#### Scenario: 重试相同请求
- **WHEN** 客户端以相同请求标识和相同内容重试多设备预约
- **THEN** 系统返回原创建结果，不重复创建租赁

#### Scenario: 单台编辑同单公共信息
- **WHEN** 操作员在某台设备的租赁编辑请求中修改同单地址、订单号或分摊金额
- **THEN** 系统拒绝该单台编辑，不改变同单其他设备的信息

#### Scenario: 单台调整独立档期
- **WHEN** 操作员只调整同单某台设备的开始日期或寄出时间
- **THEN** 系统只更新该台租赁及其库存附件，不改变同单其他主设备的独立档期

### Requirement: 区分配套附件与库存附件

手柄和镜头支架等配套附件 MUST 以主租赁上的标记保存；选中的库存附件 MUST 以关联主租赁的子租赁记录保存。编辑主租赁的附件选择时，系统 MUST 在同一事务中增删对应子租赁，并同步其仓库、租期和状态。

#### Scenario: 同时选择两类附件
- **WHEN** 操作员选择配套手柄及一个库存三脚架
- **THEN** 主租赁保存手柄标记，三脚架生成一条子租赁记录

#### Scenario: 编辑库存附件
- **WHEN** 操作员移除旧库存附件并加入新的可用库存附件
- **THEN** 系统删除旧子租赁、创建新子租赁，并保持主租赁和子租赁信息一致

### Requirement: 租赁设备选项按型号和名称排序

PC 和移动端的新建、编辑设备选项 MUST 先按型号名称、再按设备名称升序自然排序；名称中的数字按数值顺序比较。

#### Scenario: 型号和设备名称含数字
- **WHEN** 清单同时包含型号 X2、X10，以及同型号下的设备 2、设备 10
- **THEN** X2 排在 X10 前，设备 2 排在设备 10 前

### Requirement: 编辑设备清单同时提示档期与生命周期状态

PC 和移动端编辑租赁时，设备清单 MUST 分别标出设备在当前编辑租期内是否有档期冲突，以及是否已售出、损坏、停用或退役。档期查询 MUST 排除正在编辑的租赁本身；查询失败时不得把未知状态显示为可用。已有租赁当前使用的非正常生命周期设备仍须可见。

#### Scenario: 同一设备既已售出又有档期冲突
- **WHEN** 操作员打开编辑页设备清单，而某设备同时满足这两个条件
- **THEN** 清单同时显示“已售出”和“档期冲突”

#### Scenario: 修改租期后再次打开设备清单
- **WHEN** 操作员修改租赁日期或物流时间，再打开设备清单
- **THEN** 清单按修改后的时间重新检查，不沿用旧租期的查询结果

#### Scenario: 档期查询失败
- **WHEN** 查询设备冲突的请求失败
- **THEN** 清单显示档期未确认或查询失败，不显示档期可用

### Requirement: 编辑主设备允许冲突但保留其他库存限制

编辑已有租赁时，系统 MUST 提示所选主设备与其他租赁的档期重叠，并允许操作员继续保存，以支持两条租赁交换设备。更换后的设备仍 MUST 存在、属于目标仓库、处于正常可出租生命周期，且同单设备保持同一型号；库存附件的占用冲突仍 MUST 拒绝。设备和附件选择均未改变、占用时间也未改变时，原有历史选择可继续保存。

#### Scenario: 两条租赁对换主设备
- **WHEN** 两条租赁时间重叠，操作员先将第一条改用第二条的设备，再将第二条改用第一条的设备
- **THEN** 两次编辑均可在冲突提示后保存

#### Scenario: 编辑时换成已售设备
- **WHEN** 操作员将主设备换成已售出的另一台设备
- **THEN** 系统拒绝保存，原设备保持不变

#### Scenario: 编辑时选择已占用附件
- **WHEN** 操作员为租赁选择与其他租赁档期重叠的库存附件
- **THEN** 系统拒绝保存，主租赁及子租赁均保持原状

### Requirement: 编辑租赁信息原子提交

编辑页 MUST 读取当前租赁数据，允许修改租期、物流时间与单号、客户联系信息、设备、附件、状态、订单信息、代传照片及损坏备注。系统 MUST 在验证完整选择后原子提交；并发修改导致未显式提交的关键字段过期时 MUST 要求重试。

#### Scenario: 任一校验失败
- **WHEN** 编辑请求同时修改客户信息和选择一个跨仓库附件
- **THEN** 系统拒绝整个请求，客户信息、主设备和附件均保持原值

#### Scenario: 并发编辑使用过期数据
- **WHEN** 另一操作已修改租赁的设备、附件或租期，而当前编辑请求沿用旧的默认值
- **THEN** 系统拒绝按过期默认值保存，并要求重新查询

### Requirement: 保存并展示当前损坏备注

租赁 MUST 最多保存一条当前损坏备注。PC 与移动端编辑页 MUST 加载、编辑和清空它；非空备注 MUST 在编辑页明显提示。保存时备注去除首尾空白，空值存为 `null`，超过 1000 字或非字符串值 MUST 被拒绝。

#### Scenario: 编辑和清空备注
- **WHEN** 操作员保存一条备注后重新打开编辑页，再将其清空
- **THEN** 首次可看到保存的备注与提示，清空后 API 返回 `damage_note = null`

#### Scenario: 备注格式无效
- **WHEN** 编辑请求提交非字符串备注或去空白后超过 1000 字
- **THEN** 系统拒绝请求，原备注不变

### Requirement: 在疑似重复订单和物流时效不足时提示

PC 与移动端创建租赁时，系统 MUST 对客户名称或收件地址匹配的活动租赁给出重复提示，并允许操作员确认后继续。若所选物流预留天数少于按地址估算的顺丰标快时效，系统 MUST 在创建或编辑提交前提示，操作员可确认继续或取消。

#### Scenario: 发现疑似重复租赁
- **WHEN** 新建表单与活动租赁的客户名称或地址相同
- **THEN** 编辑器提示疑似重复，由操作员决定是否继续创建

#### Scenario: 物流时效不足
- **WHEN** 所选物流预留天数少于地址估算天数
- **THEN** 编辑器显示所选和估算天数，并在操作员确认后继续提交

### Requirement: 按闲鱼店铺关联和读取订单信息

租赁可保存闲鱼订单号及所属店铺。输入订单号并请求拉取订单信息时，系统 MUST 使用指定的有效店铺读取订单详情，供编辑器填充收件信息、买家信息和金额；无法确定店铺或外部服务失败时 MUST 返回明确错误。

#### Scenario: 拉取有效订单
- **WHEN** 操作员选择有效店铺并输入订单号后拉取
- **THEN** 系统返回订单的收件、买家和付款信息，编辑器可据此填充租赁表单

#### Scenario: 店铺无效
- **WHEN** 请求未选择有效店铺
- **THEN** 系统拒绝拉取，不把其他店铺的订单信息填入当前租赁

### Requirement: 更新租赁状态并同步库存附件

编辑租赁可保存 `not_shipped`、`scheduled_for_shipping`、`shipped`、`returned`、`completed`、`cancelled` 状态。通过租赁编辑或状态更新接口变更状态时，变化 MUST 同步到库存附件的子租赁；首次变为已发货且没有寄出时间时补写寄出时间，首次变为已完成且没有收回时间时补写收回时间。

#### Scenario: 主租赁完成
- **WHEN** 操作员把有库存附件的主租赁改为 `completed`
- **THEN** 主租赁和附件子租赁均为 `completed`；未填写的收回时间被补写

#### Scenario: 非法状态
- **WHEN** 编辑请求提交不在允许集合中的状态
- **THEN** 系统拒绝编辑，不改变租赁状态

### Requirement: 单条租赁发货到闲鱼

PC 与移动端编辑页可触发单条租赁的闲鱼发货操作。系统 MUST 要求该租赁已有闲鱼订单号和寄出快递单号；仅在闲鱼服务返回成功后，将该租赁标记为 `shipped`，并在缺少寄出时间时补写。外部服务失败时 MUST 保持租赁原状并返回失败信息。

#### Scenario: 成功发货
- **WHEN** 租赁具备订单号和快递单号，且闲鱼服务确认发货成功
- **THEN** 系统将该租赁标记为已发货，并返回成功结果

#### Scenario: 缺少必要单号或外部发货失败
- **WHEN** 租赁缺少订单号、快递单号，或闲鱼服务未确认成功
- **THEN** 系统不把该租赁标记为已发货，并返回错误

### Requirement: 删除租赁时清理其库存附件记录

删除主租赁 MUST 同一事务删除其库存附件子租赁；删除不存在的租赁 MUST 返回不存在错误。

#### Scenario: 删除带库存附件的主租赁
- **WHEN** 操作员删除一条带库存附件的主租赁
- **THEN** 主租赁及其关联的子租赁均被删除

#### Scenario: 删除不存在的租赁
- **WHEN** 删除请求指向不存在的租赁 ID
- **THEN** 系统返回不存在错误，不修改其他租赁
