# 批量发货“寄回在途”状态设计

## 目标

桌面端批量发货列表展示设备上一单状态时，将上一单为 `returned` 的设备从“设备在库”中区分出来，显示紫色“寄回在途”，避免把正在寄回的设备误判为已在库。

## 范围

- 仅修改桌面端 `BatchShippingView.vue` 的“设备状态”列。
- 保持 `/api/rentals/by-ship-date` 的响应结构和后端完成状态判定不变。
- 移动端批量发货卡片当前不展示上一单状态，不在本次范围内。
- 不改变订单可选、预约发货、打印或其他批量发货行为。

## 展示规则

前端按以下优先级渲染设备状态：

1. `has_previous_rental` 为假：显示 `-`。
2. `previous_rental_status === 'returned'`：显示“寄回在途”，标签颜色为紫色 `#7232dd`。
3. `previous_rental_completed` 为真：保持显示绿色“✓ 设备在库”；这继续覆盖 `completed` 和 `cancelled`。
4. 其他状态：保持显示红色“⚠ 上一单未结束”；例如 `shipped`。

必须先判断 `previous_rental_status === 'returned'`，因为后端会同时为该状态返回 `previous_rental_completed: true`。

## 实现方式

在现有 Vue 模板的条件链中插入 `returned` 专用分支，并为标签添加局部样式类。紫色使用项目既有的 `returned` 状态色 `#7232dd`，不新增全局样式或状态枚举。

## 错误处理与兼容性

本改动不增加请求、数据转换或新的错误路径。缺失上一单信息仍显示 `-`；未知且未完成的状态仍走现有警告分支。

## 测试

新增桌面端视图回归测试，覆盖：

- `returned` 显示紫色“寄回在途”。
- `completed` 仍显示绿色“设备在库”。
- `shipped` 仍显示红色“上一单未结束”。
- 无上一单仍显示 `-`。
