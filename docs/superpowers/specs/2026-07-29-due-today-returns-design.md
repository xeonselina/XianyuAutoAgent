# 今日应归还提醒列表

## 背景

租赁结束后，运营人员需要在次日提醒客户寄回设备。现有甘特图能展示档期和租赁状态，但没有聚合“今天应归还”订单的入口，容易漏跟进。

## 目标

- 在桌面端甘特图顶部提供“今日应归还”入口和待处理数量。
- 严格按“租赁结束日期 + 1 天等于今天，且状态为 `shipped`”筛选。
- 在列表中展示手机型号、租赁时间、地址、电话。
- 支持每行一键将订单标记为 `returned`。
- 将所有用户可见的 `returned` 状态文案统一为“已寄回”。

## 界面与交互

甘特图顶部新增“今日应归还”按钮，按钮显示当前待处理数量。点击按钮从右侧打开抽屉。抽屉使用表格展示主租赁记录，列为手机型号、租赁时间、地址、电话和操作。

“租赁时间”以“开始日期 至 结束日期”展示。每行提供“标记为已寄回”按钮。提交期间仅禁用当前行按钮；成功后该订单从列表移除、按钮数量同步减少，并刷新甘特图。没有待处理订单时显示“今天暂无应归还订单”。

## 后端与数据流

新增 `GET /api/rentals/due-today`。服务器使用本地日期计算目标结束日期 `today - 1 day`，查询：

- `Rental.end_date == today - 1 day`
- `Rental.status == "shipped"`
- `Rental.parent_rental_id IS NULL`

结果按设备型号和租赁 ID 稳定排序。接口返回租赁 ID、设备型号、开始日期、结束日期、地址、电话和状态。设备型号优先使用 `device.device_model.display_name`，缺失时回退到 `device.model`，最后回退到设备名称。

前端进入甘特图时加载数量，打开抽屉时再次刷新。状态变更复用 `PUT /api/rentals/<id>/status`，提交 `{"status":"returned"}`。

## 状态命名

数据库枚举值继续使用 `returned`，不新增迁移。桌面端和移动端所有用户可见的“已收回”“已还租”或“已回收”统一改为“已寄回”。`completed` 继续显示“已完成”。

## 错误与并发

- 列表加载失败时保留已有数据并显示错误提示。
- 状态更新失败时保留该行并恢复按钮可用状态。
- 同一行提交期间不能重复点击。
- 如果订单已在其他页面改过状态，下一次刷新会自然移出列表。
- 子租赁不进入提醒列表，但主租赁状态更新仍沿用现有逻辑同步子租赁。

## 测试

- 后端集成测试覆盖日期边界、状态过滤、子租赁过滤、型号回退和响应字段。
- 前端测试覆盖初始数量加载、打开抽屉刷新、一键更新状态、成功后移除与刷新甘特图、失败保留。
- 状态组件测试确认 `returned` 显示为“已寄回”。
- 运行后端相关测试、桌面端测试与构建、移动端构建。

## 非目标

- 不增加逾期多日订单。
- 不向客户自动发送消息。
- 不提供任意状态下拉框。
- 不新增数据库字段或修改 `returned` 枚举值。
