# SaaS Main Lite 轻量化改造设计

日期：2026-08-24

状态：已确认，待实施计划

目标分支：saas-main-lite

## 1. 背景

saas-main 分支尝试一次性完成租户隔离、认证、权限、订阅、邀请、仓库、库存、顺丰、闲鱼、打印、任务系统、outbox、灾备与恢复等大量能力。该分支相对 main 涉及约 901 个文件，增加约 26.7 万行，应用与测试文件数量也大幅增长，但 OpenSpec 仍有大量任务未完成。

本次不在 saas-main 上继续开发，也不合并其中的通用运行时和状态机。saas-main 只用于理解业务需求和识别过度设计。新实现从最新 main 开始，以最少的新表、最少的抽象和对现有业务结构最小的侵入完成已确认需求。

生产数据库备份为 /Users/jimmypan/Downloads/backup_20260824_080001.sql。备份来自 MariaDB 10.11，inventory_management 当前 Alembic 版本为 20260807_damage_notes。备份还包含 mysql 系统库及其他数据库，测试还原时必须只提取 inventory_management，禁止整体导入。

## 2. 目标

- 同一 MariaDB 实例中，每个租户使用独立业务数据库。
- 使用极小控制库存放租户、成员、会话和数据库连接信息。
- 超级管理员通过页面创建租户和首个 Admin。
- 租户成员使用大陆手机号和腾讯云短信验证码登录。
- 租户支持 Admin 与 Operator 两个固定角色。
- 租户具有状态和 expires_at；到期或暂停后保留数据但禁止业务操作。
- 租赁和库存增加多仓库维度。
- 每个仓库拥有独立顺丰月结配置、寄件信息和快麦打印配置。
- 每个租户支持多个闲鱼店铺，订单绑定店铺，每三分钟后台同步。
- 验货时更新主设备及实际库存附件的仓库位置。
- 生产数据库原地成为默认租户业务库，现有数据平滑迁移。
- 只交付一个可运行 app 或 worker 的镜像，以及相应环境变量示例。
- 保持代码量可审查，避免再次出现数十万行膨胀。

## 3. 明确不做

- 套餐、计费、支付、兑换码、退款。
- 邀请链接、席位预留、跨租户邀请状态机。
- 自定义角色、自定义权限或权限表达式引擎。
- 租户删除、冷静期、恢复编排和数据销毁流程。
- 超级管理员模拟租户成员或读取租户业务数据。
- 通用 outbox、事件总线、任务中心、任务尝试表、lease、fence 或 generation。
- 通用外部系统配置框架。
- 逻辑库存单位、库存申请、库存占用和库存事件系统。
- device_models.inventory_mode。
- 一仓多打印机调度。
- 多短信服务商或多快递服务商抽象。
- 登录设备列表、设备级会话撤销、手机号变更和敏感操作二次验证码。
- 自动密钥轮换和多版本密钥管理。
- 公网穿透、花生壳、FRP、Cloudflare Tunnel 或 NAS 专用配置；待用户提供 NAS 配置样例后单独适配。
- 大型端到端测试框架、重复 DTO 层和 Repository 层。

## 4. 总体架构

采用同一 MariaDB 实例、每租户独立业务库、另设一个控制库的结构。

请求处理链路为：

1. 浏览器携带 HttpOnly 会话 Cookie。
2. 应用访问控制库验证会话、成员、租户状态和 expires_at。
3. 应用从租户记录取得业务数据库信息。
4. 当前请求的现有 Flask-SQLAlchemy Session 绑定该租户 Engine。
5. 现有模型、查询和 db.session 调用继续访问当前租户业务库。
6. 请求结束后释放当前业务 Session。

平台页面和登录接口只访问控制库。租户业务接口必须完成控制库校验后才能绑定业务库。后台 Worker 不伪造 HTTP 请求，而是显式遍历租户并绑定业务库。

### 4.1 选择该方案的原因

- 相比在所有业务表加入 tenant_id，对现有五万多行代码的侵入显著更小。
- 相比每租户部署一整套应用与数据库，NAS 运维成本更低。
- 业务数据在数据库层天然分离，查询漏写 tenant_id 不会造成跨租户读取。
- 默认租户可以继续使用现有 inventory_management，无需复制或改名。

## 5. 控制库

控制库只建立 5 张核心表。

### 5.1 platform_admins

- id
- username，唯一
- password_hash
- totp_secret_ciphertext
- created_at
- updated_at

平台只有 super_admin 一种角色，不建立角色表。密码使用 Werkzeug 提供的安全密码哈希；TOTP 密钥使用统一 AES-GCM 工具加密。

### 5.2 tenants

- id
- name
- status：active 或 suspended
- expires_at
- db_name，唯一且由系统生成
- db_username，唯一且由系统生成
- db_password_ciphertext
- provisioning_status：provisioning、active 或 failed
- provisioning_error
- created_at
- updated_at

status 与 provisioning_status 分开：前者控制租户业务使用，后者只描述同步建库结果。

### 5.3 tenant_members

- id
- tenant_id
- phone，全局唯一
- role：admin 或 operator
- status：active 或 disabled
- created_at
- updated_at

一个手机号只能属于一个租户。成员由租户 Admin 直接添加，立即生效，不产生邀请记录。

### 5.4 auth_sessions

- id
- kind：platform 或 tenant
- subject_id
- tenant_id，可空
- token_hash，唯一
- csrf_token_hash
- expires_at
- created_at
- last_seen_at

浏览器只保存随机原始令牌，控制库只保存哈希。平台与租户使用不同 Cookie 名称和路径边界。

### 5.5 sms_login_codes

- id
- phone
- code_digest
- requested_ip
- send_succeeded
- attempt_count
- expires_at
- consumed_at
- created_at

验证码不保存明文。摘要使用服务端派生密钥，防止数据库泄漏后对六位数字进行离线枚举。

## 6. 控制库访问与业务库路由

- 控制库使用独立的普通 SQLAlchemy Engine 和 Session，不与现有业务模型混用。
- 现有 Flask-SQLAlchemy db 保留为业务模型入口。
- 请求开始时，为当前请求作用域的业务 Session 绑定租户 Engine。
- 使用一个小型 Engine Registry 按 tenant_id 缓存 Engine，租户连接池保持较小，避免每租户沿用当前 pool_size=10。
- 租户数据库名称、用户名和密码在创建后视为不可变；需要更换时作为单独运维操作处理。
- 平台接口不得绑定租户业务库。
- 所有业务接口默认要求有效租户会话；需要开放的健康检查和登录接口使用明确白名单。

路由边界：

- /platform/*：超级管理员登录与租户管理，只访问控制库。
- /auth/*：租户短信登录、退出和当前会话，只访问控制库。
- /api/*：校验租户会话后访问当前租户业务库。

## 7. 租户创建与生命周期

### 7.1 首次平台管理员

系统尚无平台管理员时，只允许通过一次性本地命令创建第一个超级管理员并配置 TOTP。该命令是唯一保留的身份初始化命令。之后的租户与首个 Admin 全部由平台页面创建。

### 7.2 创建租户

平台页面一次填写：

- 租户名称
- 首个 Admin 手机号
- 到期日期

同步执行：

1. 创建 provisioning 状态的租户记录。
2. 生成安全的数据库名、数据库用户名和随机密码。
3. 使用专用 Provisioner 数据库凭证创建数据库和用户并授权。
4. 对新数据库执行现有业务迁移链。
5. 创建首个 Admin 成员。
6. 将 provisioning_status 改为 active。

失败时记录安全的错误摘要并显示重试按钮。重试逻辑检查已存在的数据库和用户后继续，不建设异步 Provisioning Worker 或通用状态机。

每个租户数据库用户只拥有自身业务库权限。控制库保存加密后的随机密码。Provisioner 凭证只提供给 app，不提供给 worker。

### 7.3 到期与暂停

- active 且未过期：正常使用。
- 已过期：允许登录，只显示到期页面，业务 API 返回 TENANT_EXPIRED。
- suspended：允许登录，只显示停用页面，业务 API 返回 TENANT_SUSPENDED。
- disabled 成员：不能建立或继续使用会话。
- 成员状态、角色、租户状态和 expires_at 每次请求从控制库校验，因此变更立即生效。

平台可直接选择新的到期日期，或增加 N 天。增加天数时从当前 expires_at 与当前时间中较晚者开始计算。

## 8. 认证与权限

### 8.1 超级管理员

- 用户名
- 密码
- TOTP

不提供恢复码、密码找回工作流或平台角色层级。超级管理员仅管理租户名称、首个 Admin、状态、expires_at 和失败重试，不能查询或修改租户业务数据。

### 8.2 租户成员

租户成员通过大陆手机号和短信验证码登录。手机号全局唯一，因此无需让用户选择租户。

固定角色：

- Admin：全部业务操作，以及成员、仓库、顺丰、快麦和闲鱼配置。
- Operator：租赁、库存、发货、打印、验货和跨仓操作，不能管理成员或凭证。

不允许禁用或降级最后一个有效 Admin。前端隐藏无权按钮只改善体验，后端必须再次校验角色。

### 8.3 会话与 CSRF

- 使用 Secure、HttpOnly Cookie。
- SameSite 使用安全默认值，并按平台与租户路径隔离。
- 修改请求携带 CSRF Token。
- CSRF Token 只保存在页面内存，不写 localStorage。
- 退出登录删除服务端会话。
- 现有开放 CORS 改为同源或明确域名白名单。

## 9. 腾讯云短信

只接腾讯云短信。全局配置包括：

- TENCENTCLOUD_SECRET_ID
- TENCENTCLOUD_SECRET_KEY
- TENCENT_SMS_SDK_APP_ID
- TENCENT_SMS_SIGN_NAME
- TENCENT_SMS_TEMPLATE_ID

SecretId 与 SecretKey 由 NAS 运行环境注入，不写控制库、不进入镜像、不由页面管理。

只安装 tencentcloud-sdk-python-common 与 tencentcloud-sdk-python-sms，不安装全产品 SDK。

验证码规则：

- 仅接受大陆手机号，发送时转换为 +86 E.164 格式。
- 使用密码学安全随机数生成六位数字。
- 五分钟有效。
- 最多尝试五次，成功后立即作废。
- 腾讯云返回 Code=Ok 后才可用于登录。
- 同一手机号 60 秒内最多请求一次、每小时 5 次、每天 10 次。
- 同一 IP 每小时最多 30 次。
- 不存在或已禁用的手机号不发送，但接口返回与正常请求相同的通用提示。
- 发送新验证码时顺便删除超过保留期的旧记录，不增加清理任务。

腾讯云控制台的频率限制不得低于应用限制。上线前需完成实名资质、签名、运营商报备、验证码模板审核和套餐购买。NAS 必须启用准确的时间同步。

模板建议：您的登录验证码为：{1}，{2}分钟内有效，请勿泄露。

自动测试使用 Fake Sender。开发环境允许配置固定验证码，但生产模式检测到开发验证码配置时拒绝启动。

## 12. 仓库与库存操作

### 12.1 当前仓库

- 只有一个仓库时自动选择，不增加操作步骤。
- 多仓库时顶部提供当前仓库选择器。
- 库存、甘特图和租赁列表可以查看当前仓库或全部。
- 新增设备和租赁默认使用当前仓库。
- 设备当前 warehouse_id 是库存位置事实来源，不另建库存台账。

### 12.2 创建设备与租赁

创建租赁时先确定履约仓库：

1. 主设备只显示该仓库中在租期内可用的设备。
2. 手机支架、三脚架等实际库存附件也只显示同仓且可用的设备。
3. 主租赁和子租赁统一写入同一个 warehouse_id。
4. 配套手柄、镜头支架继续使用现有布尔字段，随主设备走，不产生独立仓位。

闲鱼店铺绑定：

- 从闲鱼告警创建租赁时自动继承告警店铺。
- 手工录入闲鱼订单时，只有一个启用店铺则自动选择；多个启用店铺则要求选择。
- 非闲鱼订单允许不绑定店铺。
- 订单详情和发货通知始终使用租赁绑定店铺的凭证。

### 12.3 发货前校验

顺丰下单前检查：

- 租赁已绑定仓库。
- 主设备仍在该仓库。
- 所有实际附件仍在该仓库。
- 仓库顺丰账号、月结卡和寄件信息完整。
- 已有运单号时不得再次下单。

打印前检查仓库快麦配置和 printer_sn。

顺丰客户订单号使用稳定的租户标识加租赁 ID，避免不同租户或仓库复用 partner_id 时发生冲突。重试沿用同一客户订单号，不生成新的业务订单号。

### 12.4 跨仓移动与自动修正

移动设备前查找使用该设备的未来未发货租赁，展示影响清单。

- 主设备移仓：租赁仓库跟随主设备；不同仓附件自动尝试替换为目标仓同型号可用设备。
- 只有附件移仓：租赁仓库保持不变；自动尝试在原履约仓寻找同型号附件替换。
- 任一租赁缺少替代设备时，该租赁完全不修改并明确列出缺口。
- 支持一次确认批量处理。
- 已生成运单或已经发货的租赁不能自动修改，只提示人工处理。

仓位变更复用现有 audit_logs，不增加库存事件表。

### 12.5 归还验货

- 验货页面增加收货仓库，默认原履约仓库，也可选择实际收货仓库。
- 验货完成的同一事务中，更新主设备以及本次实际收到的所有 Device 附件 warehouse_id。
- 已完成租赁保留原履约仓库作为历史记录，不因归还到其他仓库而改写。
- 仓位变化影响未来租赁时，立即显示影响清单和一键修正操作。

## 13. 顺丰、快麦与闲鱼服务

移除从环境变量读取单一租户业务凭证的全局服务实例。服务改为显式传入当前仓库或店铺配置：

- SFExpressService(sf_config)
- KuaimaiPrintService(kuaimai_config)
- XianyuOrderService(shop_config, global_api_domain)

### 13.1 顺丰

- 下单、面单、轨迹查询都按租赁 warehouse_id 解析顺丰配置。
- 独立手工轨迹查询若无法通过运单匹配租赁，则要求选择仓库。
- 寄件人姓名、电话、详细地址从仓库顺丰配置读取。
- 不再使用硬编码寄件人默认值。
- 不实现完整取消、更新、未知结果恢复状态机或通用 outbox。
- 批量下单继续逐条返回结果，单条失败不隐式生成复杂重试记录。

### 13.2 快麦

- 打印按租赁 warehouse_id 解析 app_id、app_secret 和 printer_sn。
- 打印失败直接返回错误，用户可重打。
- 不保存通用打印任务或打印机调度记录。

### 13.3 闲鱼

- 同一租户支持多个启用店铺。
- 每个店铺独立实例化 API Client。
- 订单对账只与同一 xianyu_shop_id 的租赁比较。
- 完整分页成功后才更新该店铺告警缓存及 last_success_at。
- 任一分页失败时保留原告警，错误摘要写入 last_error。
- 店铺停用后停止后台同步，历史绑定保持不变。
- 闲鱼发货使用租赁绑定店铺；需要寄件信息时复用租赁仓库寄件人配置。

## 14. Worker

app 与 worker 使用同一个镜像、不同启动命令。

当前代码导入 APScheduler，但 requirements.txt 未安装它；项目已经安装 schedule==1.2.0。因此新 Worker 使用现有 schedule 库，不新增 APScheduler。

Worker 只运行两个固定任务：

- 每 60 秒处理到达预约时间的发货租赁。
- 每 180 秒逐租户、逐启用店铺同步闲鱼订单。

执行规则：

- 只处理 active 且未过期租户。
- 每个租户显式绑定其业务库。
- 单租户或单店铺失败只记录错误并继续。
- 单进程顺序执行，任务不重叠。
- 在控制库持有 MariaDB advisory lock，避免误启动两个 Worker。
- Docker 或 NAS 容器机制负责进程重启。
- 不保存 job、attempt、lease、fence 或 generation。

预约发货中，闲鱼通知失败时租赁保持待处理，下次调度自然重试。已完成租赁不会再次进入查询范围。

## 15. 页面设计

### 15.1 租户页面

- /access-restricted：到期或暂停说明。
- /settings：成员、仓库、闲鱼店铺三个标签。

现有业务页面保持原路由。顶部增加租户名称、当前仓库、当前角色、设置入口和退出登录。

仓库设置使用列表加编辑抽屉：

- 基本信息
- 顺丰配置
- 快麦与打印机配置

每部分显示已配置或未配置。敏感字段不回传原文；输入框留空代表保持原值，填写才替换。

闲鱼店铺使用列表与新增或编辑弹窗，展示启用状态、最近成功时间和最近错误，并提供单店铺立即同步。

成员页支持添加手机号、选择角色、修改角色、禁用和重新启用。

### 15.2 平台页面

租户列表使用创建或编辑抽屉，支持创建租户与首个 Admin、修改到期时间、增加天数、暂停、恢复和失败重试。不提供业务数据入口和模拟登录。

## 16. 密钥与日志

使用一个小型 AES-GCM 工具加密：

- 租户数据库密码
- 平台 TOTP 密钥
- 顺丰 checkword 与月结卡
- 快麦 app_secret
- 闲鱼 app_secret

主密钥由用户保存在密码管理器中，运行时通过 NAS 支持的安全方式注入。仓库、数据库、镜像、日志和 Git 中均不得保存主密钥。首版不实现密钥版本和自动轮换。

API 不返回任何密钥明文。可以返回是否已配置和必要的尾号掩码。

删除现有以下日志行为：

- 快麦 app_secret。
- 顺丰完整请求、月结卡、地址和电话。
- 闲鱼完整敏感请求。
- 腾讯云验证码和完整手机号。

日志仅记录租户、仓库、店铺、租赁等内部 ID，手机号应掩码显示。

## 18. 生产数据迁移

### 18.1 安全还原

本地测试使用独立 MariaDB 10.11 容器、独立端口和独立 Volume。只提取备份中的 inventory_management 段，显式拒绝 mysql 系统库及其他数据库。原始 SQL 不修改、不提交 Git。

### 18.2 默认租户

默认租户业务库继续是 inventory_management：

1. 建立控制库和默认租户记录。
2. 为 inventory_management 创建受限租户数据库用户。
3. 创建默认仓库占位记录。
4. 所有现有 Device，包括手机支架和三脚架等实际库存附件，绑定默认仓库。
5. 所有现有主租赁和子租赁绑定默认仓库。
6. 将现有闲鱼凭证迁移为默认店铺。
7. 已有闲鱼租赁、告警和同步状态绑定默认店铺。
8. 将现有顺丰与快麦配置迁入默认仓库；缺失的寄件配置保持未完成。
9. 校验完成后设置必要的非空约束。

默认仓库配置不完整时，只阻止顺丰下单和打印，不影响查看或整理现有数据。

### 18.3 迁移前检查

- 记录迁移前所有业务表行数。
- 检查闲鱼订单组合唯一性冲突。
- 检查无父租赁、无设备和空订单号。
- 检查所有设备与租赁可以绑定默认仓库。
- 检查子租赁与父租赁关系。

### 18.4 上线与回滚

正式迁移前停止旧应用和 Worker，进入维护状态，生成完整生产备份并在隔离环境验证该备份可以恢复，同时保存旧镜像和旧运行配置。

MariaDB DDL 不依赖自动 downgrade。正式接流量前失败直接恢复完整备份。接流量后如果已有新数据，不执行未经确认的自动数据库回滚，优先修复前进，避免丢失新订单。

## 19. 测试策略

保留现有测试并增加聚焦测试：

- 两个租户存在相同主键时的数据隔离。
- 请求 Session 的租户 Engine 绑定与释放。
- Admin、Operator、Super Admin 权限。
- 到期、暂停和成员禁用实时拦截。
- 腾讯云短信验证码摘要、有效期、尝试次数与限流。
- 仓库内设备和附件可用性。
- 跨仓移动和自动替换的全有或全无事务。
- 验货后主设备与实际附件仓位同步。
- 租赁绑定仓库和闲鱼店铺。
- 顺丰、快麦、闲鱼配置解析与脱敏。
- 多店铺三分钟同步和单店失败隔离。
- 生产 SQL 还原后的完整迁移及数据不变量校验。
- 现有租赁、库存、顺丰、闲鱼、打印、验货、统计和接力回归。
- Vue 登录、仓库选择、设置权限和跨仓影响弹窗的关键交互。

MariaDB 枚举、外键、权限和迁移测试必须使用 MariaDB 10.11，不用 SQLite 替代。外部服务在自动测试中使用 Fake 或 Mock；真实联调作为受控冒烟测试。

## 20. 运行与交付

NAS 生产运行方式不使用项目 Docker Compose。用户稍后提供 NAS 独有配置样例，本次不提前改写。

交付范围只有：

- app 进程
- worker 进程

两者使用同一个镜像和不同启动命令。镜像不包含数据库、Redis、Nginx、反向代理、.env 或任何真实密钥。

本次准备：

- 可按 app 或 worker 启动的镜像。
- 完整 .env.example。
- 本地 .env 中补齐新增配置项但保持 Git 忽略。
- 本地 MariaDB 10.11 测试库启动和生产 SQL 安全还原工具。

公网入口方案在确认 NAS 是否有稳定 IPv4 或可用 IPv6、并取得 NAS 配置样例后再决定。业务代码只保留标准反向代理、可信代理、HTTPS 和公开基础 URL 配置，不绑定花生壳、FRP 或 Cloudflare。

## 21. 代码规模约束

- 生产代码目标增加约 8,000 至 15,000 行。
- 测试代码目标增加约 5,000 至 10,000 行。
- 新增生产文件目标不超过约 30 个。
- 新增测试文件目标不超过约 20 个。
- 生产代码超过 20,000 行，或全部新增手写代码超过 30,000 行时暂停实施并请求用户决策。
- 控制库固定 5 张表；业务库固定新增 4 张表。新增其他业务表必须先取得用户同意。
- 控制库从一条基线迁移开始；业务 SaaS 改造控制在 1 至 2 条迁移。
- 新抽象必须至少服务两个已确认场景，否则留在具体业务模块。
- 优先修改现有 Service、Handler、Model 和 Vue 页面，不在外面堆叠多层包装。

## 22. 验收标准

1. 超级管理员页面可以创建租户和首个 Admin，失败可以重试。
2. 租户成员可以通过腾讯云验证码登录；角色、到期、暂停和成员状态立即生效。
3. 两个租户即使存在相同设备或租赁 ID，也不能互相读取或修改数据。
4. 生产 SQL 可以在 MariaDB 10.11 中安全还原并迁移为默认租户，迁移前后数据校验通过。
5. 多仓库租赁、库存筛选、跨仓影响提示、自动修正和验货入仓完整可用。
6. 每仓库独立使用顺丰账号、月结卡、寄件信息和快麦打印机。
7. 每租户支持多个闲鱼店铺，订单绑定店铺，Worker 每三分钟独立同步。
8. 原有租赁、库存、顺丰、闲鱼、打印、验货、统计和接力业务通过回归测试。
9. 日志、API、镜像和 Git 中没有真实密钥、月结卡、验证码或未掩码敏感信息。
10. 最终镜像支持 app 与 worker 两种启动命令；NAS 专用配置等待用户样例后适配。

## 23. 实施顺序原则

实施计划必须按可验证的纵向切片组织，而不是先搭建大平台：

1. 测试数据库与迁移安全网。
2. 控制库、密钥工具和请求路由。
3. 平台管理员、租户创建和短信登录。
4. 仓库及配置表。
5. 设备、租赁、验货和跨仓流程。
6. 顺丰、快麦和闲鱼按仓库或店铺解析。
7. 独立 Worker。
8. 前端页面和完整回归。
9. 镜像、环境变量和 NAS 配置适配。

每个阶段都必须先写失败测试，再实现最小代码，再运行相关回归。发现必须重构现有核心架构或突破本设计规模边界时，停止实施并由用户决定。
