# 甘特图告警出现后的滚动修复设计

## 背景

甘特图页面外层 `.gantt-view` 固定为一屏高度并隐藏溢出内容，内部
`.gantt-container` 又使用 `min-height: 100vh`。甘特图滚动区域同时设置了
`min-height: 400px` 和基于视口的 `max-height`。

真实浏览器复现还确认了第二个根因：设备行包含名称、序列号和生命周期选择器，
实际显示高度约为 94px，但虚拟列表仍按 44px 计算。滚动窗口切换后，实际内容
高度会改变，导致滚动位置跳动并再次把最后一行推到底部之外。

当“发现 N 笔待发货订单尚未录入库存管理”提示异步出现或展开详情时，它会
增加页面内固定内容的高度，但甘特图没有从剩余空间中重新计算高度。多出的底部
内容被外层裁剪，虚拟列表仍使用旧的可见高度，最终表现为滚动到底时屏幕抖动且
最后一行无法显示。

## 目标

- 提示条单行显示、展开详情和收起详情时，甘特图均自动使用剩余可用高度。
- 甘特图纵向滚动能够稳定到达并完整显示最后一台设备。
- 保持现有横向滚动、固定表头和虚拟列表行为。
- 不把整个页面改成第二个纵向滚动容器。

## 设计

### 高度约束

建立从页面到甘特图滚动区的连续 flex 高度链：

1. `.gantt-view` 继续固定为一屏高度并隐藏页面级溢出。
2. `.gantt-container` 改为占满父容器高度，设置 `min-height: 0` 和
   `overflow: hidden`。
3. 工具栏、提示条和筛选器保持自然高度，不参与压缩。
4. `.gantt-main` 使用剩余高度，设置 `min-height: 0`、`display: flex` 和
   `overflow: hidden`。
5. `.gantt-scroll-container` 占满主体剩余空间，设置 `min-height: 0`，继续负责
   横向滚动。
6. `.gantt-body` 移除固定的 400px 最小高度和视口 `max-height`，改为
   `flex: 1`、`min-height: 0`，只负责纵向滚动。

这样提示条高度发生变化时，只会改变甘特图滚动区的可用高度，不会把内容推出
一屏页面边界。

### 虚拟列表同步

在 `.gantt-body` 上注册 `ResizeObserver`。每次滚动区高度变化时重新执行现有的
可见区间计算，确保提示条出现、展开或收起后，可见行数与实际容器高度一致。
组件卸载时断开 observer，避免残留回调。

将虚拟列表步长和每个 `GanttRow` 的固定显示高度统一为 94px。这个值与修复前
真实显示尺寸一致，不会放大界面；它只纠正旧的 44px 计算值。虚拟容器额外保留
1px 底部空间，避免浏览器小数像素取整裁掉最后一行的底边。

若运行环境不支持 `ResizeObserver`，保留现有滚动和数据变化触发的计算路径，
页面不会因此初始化失败。

## 测试

- 新增组件回归测试，模拟甘特图滚动区高度变化，验证 observer 会重新计算虚拟
  可见范围，并且增长后的视口会渲染新增可见行。
- 验证虚拟步长、实际行高和底部缓冲保持一致，滚动高度不会随可见窗口改变。
- 验证组件卸载时 observer 被断开。
- 运行相关甘特图组件测试、完整前端测试、类型检查和生产构建。
- 使用真实浏览器检查提示条单行、展开、收起三种状态下最后一行均可滚动显示。

## 非目标

- 不调整闲鱼漏录订单的查询或提示内容。
- 不改变设备筛选、租赁数据或修复前的实际视觉行高。
- 不重构甘特图的横向滚动结构。
