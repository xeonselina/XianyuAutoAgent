# 待归还订单分组展示

## 背景

现有“今日应归还”功能只查询租赁结束日期为昨天的订单。若运营人员当天没有及时处理，订单从第二天起会从提醒入口消失，导致逾期待归还订单无法继续跟进。

本设计扩展现有提醒范围，将今天应归还及更早仍未寄回的订单统一纳入“待归还”，并按逾期时间段分组展示。本文取代 `2026-07-29-due-today-returns-design.md` 中“只包含今天应归还订单”和“不增加逾期多日订单”的约束，其余状态更新与错误处理规则继续有效。

## 目标

- 展示今天及以前应归还、当前仍为 `shipped` 的主租赁记录。
- 将入口、抽屉、空状态和内部领域命名统一为“待归还”。
- 按“今日”“逾期 1–3 天”“逾期 4–7 天”“逾期超过 7 天”分组。
- 保留现有一键标记为 `returned`、行级加载、防重复提交和错误恢复能力。
- 为现有 `/api/rentals/due-today` 调用保留兼容入口。

## 日期口径

服务器本地日期是唯一日期口径，前端不根据浏览器日期重新计算逾期天数。

- `due_date = end_date + 1 天`
- `overdue_days = today - due_date`
- `overdue_days == 0`：今日
- `1 <= overdue_days <= 3`：逾期 1–3 天
- `4 <= overdue_days <= 7`：逾期 4–7 天
- `overdue_days >= 8`：逾期超过 7 天

只有满足以下全部条件的记录进入待归还列表：

- `Rental.end_date <= today - 1 天`
- `Rental.status == "shipped"`
- `Rental.parent_rental_id IS NULL`

未来才应归还的订单、已寄回或已完成订单、已取消订单和子租赁均不进入列表。

## 后端接口与数据结构

新增规范接口：

```text
GET /api/rentals/pending-returns
```

原接口作为兼容别名保留，并调用同一处理器：

```text
GET /api/rentals/due-today
```

两个接口返回相同的平铺结构：

```json
{
  "success": true,
  "data": {
    "count": 2,
    "rentals": [
      {
        "id": 12,
        "device_model": "iPhone 15 Pro Max",
        "start_date": "2026-07-20",
        "end_date": "2026-07-28",
        "due_date": "2026-07-29",
        "overdue_days": 3,
        "destination": "浙江省杭州市西湖区测试路 88 号",
        "customer_phone": "13900139000",
        "status": "shipped"
      }
    ]
  }
}
```

查询结果按 `overdue_days` 从大到小排序，逾期更久的订单优先；逾期天数相同时按租赁 ID 升序稳定排序。设备型号仍优先使用 `device.device_model.display_name`，缺失时依次回退到 `device.model` 和设备名称。

服务、处理器、前端组合式函数、类型和组件的内部命名从 `DueToday...` 统一调整为 `PendingReturns...`。数据库字段和状态枚举不变，不新增迁移。

## 前端分组与展示

甘特图顶部入口文案改为“待归还”，角标显示接口返回的全部待处理数量。点击后打开右侧“待归还”抽屉并重新加载列表。

前端只根据服务端返回的 `overdue_days` 分组，不重复计算日期。分组固定按以下顺序展示：

1. 今日
2. 逾期 1–3 天
3. 逾期 4–7 天
4. 逾期超过 7 天

空分组不渲染。每个非空分组的标题展示分组名称和订单数量。组内沿用服务端顺序，因此逾期更久的订单优先。

每条订单继续展示手机型号、租赁起止时间、地址、电话和“标记为已寄回”操作；在租赁时间下增加“应归还：`due_date`”。抽屉沿用兼容 Element Plus splitter 的像素尺寸，避免再次出现只有遮罩而面板宽度为零的问题。

没有任何待处理订单时显示“暂无待归还订单”。

## 状态更新与错误处理

状态更新继续复用：

```text
PUT /api/rentals/<id>/status
{"status": "returned"}
```

- 同一行提交期间不能重复点击，其他行仍可操作。
- 更新成功后立即从本地列表移除该订单，再重新加载列表。
- 行被移除后，分组数量和顶部总角标通过当前列表自动同步。
- 某分组最后一条订单被移除后，该空分组不再显示。
- 更新失败时保留订单并恢复该行按钮。
- 更新成功但后续列表刷新失败时，保留本地移除结果，避免误报状态更新失败。
- 列表加载失败时保留已有数据并显示错误提示。
- 订单若已在其他页面变更状态，下一次刷新会自然移出列表。

## 测试策略

后端集成测试覆盖：

- 今天应归还、逾期 1 天、逾期 3 天、逾期 4 天、逾期 7 天和逾期 8 天的边界。
- 未来应归还、非 `shipped` 状态和子租赁过滤。
- `due_date`、`overdue_days`、总数和稳定排序。
- 设备型号回退。
- 新旧两个接口返回相同结果。

前端单元与流程测试覆盖：

- 加载规范的 `/api/rentals/pending-returns` 接口并保存完整列表。
- 四个分组的边界、固定展示顺序和组内排序。
- 空分组隐藏及全部为空时的空状态。
- 分组标题数量、顶部总角标和标记已寄回后的同步更新。
- 行级加载、防重复提交、错误保留和刷新失败兜底。
- Element Plus 抽屉尺寸仍使用 splitter 支持的像素或百分比格式。

完成后运行后端待归还接口测试、桌面端完整测试、类型检查和生产构建。

## 非目标

- 不自动向客户发送提醒消息。
- 不增加任意状态下拉框或批量状态更新。
- 不修改 `returned` 枚举值或数据库结构。
- 不在前端根据浏览器时区重新计算 `due_date` 或 `overdue_days`。
- 不删除旧的 `/api/rentals/due-today` 兼容接口。
